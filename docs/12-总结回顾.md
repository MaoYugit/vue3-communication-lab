## 1. 全景回顾（10min）

### 所有通信模式一览

| 课时 | 模式 | 关系 | 方向 | 一句话描述 |
|------|------|------|------|-----------|
| 03 | Props | 父子 | 父→子 | 父组件给子组件传数据 |
| 04 | Emit | 父子 | 子→父 | 子组件通知父组件 |
| 05 | v-model | 父子 | 双向 | 父子双向数据绑定 |
| 06 | $attrs | 祖→孙 | 跨层透传 | 中间组件透传未声明属性 |
| 07 | ref + expose | 父→子 | 命令式 | 父组件主动调子组件方法 |
| 08 | provide/inject | 祖→后代 | 跨层注入 | 祖先提供数据，后代注入 |
| 09 | Pinia | 任意 | 全局共享 | 全局状态管理 |
| 10 | Mitt | 任意 | 事件广播 | 全局事件总线（发布/订阅） |
| 11 | Slot | 父→子 | 模板注入 | 父组件控制子组件的渲染内容 |

### 按照组件关系分类

```
父子通信
  ├── Props（父→子，数据）
  ├── Emit（子→父，事件）
  ├── v-model（双向，语法糖）
  ├── ref + expose（父→子，命令式调用）
  └── Slot（父→子，模板注入）

跨层级通信
  ├── $attrs（祖→孙，透传属性）
  └── provide/inject（祖→后代，依赖注入）

任意组件通信
  ├── Pinia（全局状态管理）
  └── Mitt（事件总线）
```

## 2. 场景匹配练习（15min）

**教师提出场景，学生回答应该用哪种通信方式：**

| 场景 | 答案 |
|------|------|
| 父组件需要展示子组件传入的用户名 | Props |
| 点击子组件的按钮，父组件弹出对话框 | Emit |
| 封装一个自定义输入框 | v-model |
| 封装一个 UI 组件，需要透传原生属性 | $attrs |
| 父组件想触发表单校验 | ref + expose |
| 深层嵌套的孙组件需要读取用户配置 | provide/inject |
| 两个完全不相关的组件共享登录状态 | Pinia |
| 某个操作完成后，触发一个全局通知 | Mitt |
| 父组件想自定义子组件的列表项样式 | Slot（作用域插槽） |

## 3. 架构思维培养（10min）

### 选择的优先级原则

```
能用 Props 解决的，不要用 Pinia
能用 Emit 解决的，不要用 Mitt
能用 provide/inject 解决的，不要用全局状态
能用局部 ref 解决的，不要用任何通信
```

**核心原则：适度耦合 > 过度解耦**

- Props/Emit：显式、可追踪 → 优先级最高
- provide/inject：方便但有隐式依赖 → 适度使用
- Pinia：强大但有全局耦合 → 用于真正的"全局"状态
- Mitt：事件总线 → 最后的选择，谨慎使用

### 一个真实的组件通信示例

让同学们想一个真实的页面（比如电商的商品详情页），讨论其中使用到的通信模式：

- 商品信息 → Props（父→子）
- 加入购物车 → Emit（子→父）
- 搜索框 → v-model
- 用户登录状态 → Pinia
- 主题色切换 → provide/inject
- 全局提示消息 → Mitt
- 自定义按钮组件 → $attrs
- 列表自定义渲染 → Slot
